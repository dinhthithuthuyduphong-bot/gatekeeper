3. Repository-Specific Knowledge (Jinja2)
- Project Structure: Source code is in `src/jinja2/`. Key modules include:
  - `runtime.py`: Runtime components like `Context`, `LoopContext`, and `Undefined` types.
  - `filters.py`: Built-in template filters (e.g., `map`, `select`, `join`).
  - `compiler.py` & `parser.py`: Template parsing and dynamic Python code generation.
  - `environment.py`: Core `Environment` and `Template` definitions.
  - `nativetypes.py`: Support for native Python types environments.
- Local Execution: Always prefix your execution commands with `PYTHONPATH=src` to ensure your local modifications are loaded instead of a system-installed package (e.g., `PYTHONPATH=src python3 reproduce.py`).
- Running Tests: Use `PYTHONPATH=src python3 -m pytest tests/` to run the test suite and verify no regressions were introduced. To speed up debugging, target specific test files (e.g., `PYTHONPATH=src python3 -m pytest tests/test_filters.py`).

4. Debugging Strategies
- Always create a minimal reproduction script (`reproduce.py`) to verify the bug locally before attempting a fix. 
- When fixing object representations (e.g., `Undefined` types), remember that Jinja2 heavily relies on magic methods like `__str__`, `__html__` (used during template rendering with autoescape), and `__getattr__`. If you modify how an object renders, check if `__html__` needs to be updated alongside `__str__`.
- If debugging template execution or rendering issues, remember that Jinja compiles templates to raw Python code. You can inspect the compiled source by calling `env.compile(source)` and looking at the generated AST or string to understand compiler-level bugs.
